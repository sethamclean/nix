# Nix Workspace

This repo defines package profiles for each place I work, plus the NixOS desktop.
Dotfiles are not managed here: they come from the `dotfiles` repo's `bootstrap.sh` (stow).

| Target | Package profile | System config |
| --- | --- | --- |
| NixOS desktop (dual boot) | `.#desktop` | `nixosConfigurations.desktop` |
| Codespaces image | `.#default` (`.#codespace`), `.#codespace-daemons` | `docker/Dockerfile` |
| Ubuntu work laptop | `.#laptop` | apt and the corporate image |

## Layout

- `nix/groups.nix` defines named package groups: `core`, `ai`, `build`, `lang`, `cloud`, `gui`, `daemons`.
- `nix/profiles.nix` composes the groups into one list per target. Add or move a package in a group, and every profile that includes the group picks it up.
- `hosts/common.nix` holds NixOS settings shared by every host. `hosts/desktop/` holds the desktop (`hardware-configuration.nix` was generated by `nixos-generate-config`).
- `flake.nix` exposes each profile as `packages.<system>.<name>` and the desktop as `nixosConfigurations.desktop`.

## Update Matrix

| Target | Source of truth | How to apply |
| --- | --- | --- |
| Desktop system and user tools | `hosts/desktop/`, `hosts/common.nix`, the `desktop` profile | `sudo nixos-rebuild switch --flake ~/ws/nix#desktop` |
| Ubuntu laptop user tools | the `laptop` profile | `nix profile install ~/ws/nix#laptop`, later `nix profile upgrade laptop-packages` |
| Codespaces daemon profile (`seth`) | `.#codespace-daemons` | Rebuild the Docker image |
| Codespaces user tools | `.#default` | Rebuild the Docker image, or run `nix profile upgrade nix` from `~/ws/nix` |
| Image OS packages | `docker/Dockerfile` apt steps | Rebuild the Docker image |
| Dotfiles | the `dotfiles` repo | `./bootstrap.sh` in that repo |

## Desktop Notes

- The desktop is NixOS with GNOME, PipeWire, NetworkManager, Firefox (`programs.firefox`) and Google Chrome (system package, unfree).
- User tools come from the `desktop` profile through `users.users.seth.packages`. Rootless Docker (`virtualisation.docker.rootless`; the daemon is a `seth` user service, `DOCKER_HOST` is set for the session, ports below 1024 cannot be bound) and Tailscale (`services.tailscale`; run `sudo tailscale up` once) are enabled in `hosts/desktop/`. Other services belong there too, as NixOS options, not packages.
- OpenShell: the `openshell` CLI is in the `ai` group. The desktop also runs the gateway (`hosts/desktop/openshell.nix`) as a rootless Podman container under a `seth` systemd user service, `openshell-gateway`, bound to `127.0.0.1:8080`. OpenShell `0.1.0` is the minimum. `nix/overlays.nix` uses nixpkgs' `openshell` when it is `0.1.0` or newer, and otherwise falls back to the upstream `0.1.x` release binaries packaged in `nix/pkgs/openshell.nix` (nixpkgs had `0.0.116` at the time). The gateway image tag follows whichever CLI version is in use. Delete the fallback file and overlay branch once nixpkgs is past `0.1.0`. After the first `switch`, wait for the service to start (it pulls the image and generates mTLS certs into `~/.local/share/openshell-gateway/tls`), then register it once with `openshell gateway add https://127.0.0.1:8080 --local --name local` and check with `openshell status`. `OPENSHELL_LOCAL_TLS_DIR` is set for login sessions so the CLI finds the same certs. Logs: `journalctl --user -u openshell-gateway`.
- Secure Boot uses `lanzaboote` (`hosts/desktop/secureboot.nix`), which replaces systemd-boot with signed boot images. Keys live in `/var/lib/sbctl`. Windows has its own ESP and keeps booting because the Microsoft keys are enrolled too. Order matters:
  1. `sudo sbctl create-keys` (must exist before the rebuild)
  2. `sudo nixos-rebuild switch --flake ~/ws/nix#desktop`, then `sudo sbctl verify` (every file except `kernel-*` should be signed)
  3. Reboot into the firmware setup and put it in Setup Mode by deleting only the Platform Key (PK). Do not clear all keys: that drops the `dbx` revocation list. Leave Secure Boot off for now.
  4. Boot NixOS, confirm Setup Mode (`od -An -tu1 -j4 -N1 /sys/firmware/efi/efivars/SetupMode-*` prints `1`), then `sudo sbctl enroll-keys --microsoft`. The Microsoft keys are needed for Windows and the GPU option ROM.
  5. Reboot into the firmware setup, enable Secure Boot, and boot NixOS. `bootctl status` should say `Secure Boot: enabled (user)`.
  If NixOS does not boot, switch Secure Boot back off in the firmware; that restores the previous behavior.
- `hosts/desktop/hardware-configuration.nix` is machine-specific. Regenerate it with `nixos-generate-config` only if the disks change.
- Flakes ignore untracked files: `git add` new files before `nixos-rebuild`.

## Ubuntu Laptop Notes

- Install Nix (multi-user) once, then install the `laptop` profile. It has the core, language, cloud and build tools, and no GUI apps or daemons.
- Docker, browsers and other desktop apps stay with apt or the corporate image. Nix GUI apps need `nixGL` on non-NixOS hosts.
- Run `~/ws/dotfiles/bootstrap.sh` for dotfiles, as on every other target.

## Codespaces Notes

- `seth` is the interactive user and gets the `.#default` Nix profile.
- Root-run services use a dedicated daemon profile at `/nix/var/nix/profiles/per-user/seth/daemons` populated from `.#codespace-daemons`.
- `codebase-memory-mcp` runs under supervisord as `seth` with its UI on port `9749`, and a companion indexer re-indexes every git repo under `/workspaces` every 10 minutes (`CBM_ALLOWED_ROOT=/workspaces`).
- `ws-doc-server` runs under supervisord as `seth` on `127.0.0.1:8765` from `/home/seth/.local/bin/ws-doc-server` (installed by `make install` in `/workspaces/mcp-servers/ws-doc-server`). It fails with a clear log message if the binary is missing.
- `tmux-mcp` runs under supervisord as `seth` on `127.0.0.1:8766` (MCP over HTTP at `/mcp`, read-only) from `/home/seth/.local/bin/tmux-mcp`, installed by `make install` in `/workspaces/mcp-servers`. It fails with a clear log message if the binary is missing.
- `sudo` is installed in the image and `seth` has passwordless sudo for container admin tasks.
- `~/ws` is the canonical workspace path. In Codespaces it points at `/workspaces`.

## Browser Testing

The user toolchain includes `playwright-test`, with its matching Nix-packaged browsers.
Run `playwright test` directly; its wrapper supplies the browser path and Node
module search path for `@playwright/test`. No `playwright install` or system
library installation is needed. Project-local Playwright dependencies must match
the version reported by `playwright --version` to use these browser revisions.

To install only this tooling without rebuilding the full user toolchain:

```bash
nix profile install .#browser-testing
```

## Cache Strategy

- Docker builds cache through both GitHub Actions cache storage and a registry-backed `buildcache` tag in GHCR.
- The expensive Nix profile layers only depend on `flake.nix`, `flake.lock`, and `nix/`, so docs and workflow edits do not invalidate them.
- Nix still pulls prebuilt store paths from upstream binary caches when a Docker layer cache miss happens.
- The image build runs daily to keep the Docker cache warm and refresh the base image.
- `flake_update.yml` runs weekly to refresh pinned Nix inputs.
- `cleanup.yaml` runs weekly and keeps the latest 10 container versions so cache continuity is less likely to be pruned away.

## Typical Commands

```bash
# Verify flake outputs
nix flake show .

# Rebuild the Codespaces image locally
docker build -f docker/Dockerfile .

# Build the desktop config without switching
nix build .#nixosConfigurations.desktop.config.system.build.toplevel

# Upgrade the user profile in an existing Codespace after changing a group in nix/groups.nix
cd ~/ws/nix
nix profile upgrade nix
```
